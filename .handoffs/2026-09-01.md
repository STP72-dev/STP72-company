## Decisions Made

- **Bun builder + `node:24-slim` runtime** — because Bun enforces the committed lockfile while Debian slim provides a compact, glibc-compatible non-root Nitro runtime.
- **`NITRO_PRESET=node-server` explicitly set in builder stage** — because `@lovable.dev/vite-tanstack-config` defaults to a Cloudflare Worker preset, which outputs a handler export rather than a standalone Node HTTP server listener.
- **Amazon ECS Express Mode + Amazon ECR is the approved compute target** — because AWS has closed App Runner to new customers, this AWS account has no App Runner services, and AWS recommends ECS Express Mode as the managed container successor.
- **Bun is the canonical dependency installer** — because `bun.lock` and `bunfig.toml` are already committed and the existing npm-based GitHub workflow is blocked before validation by the absence of an npm-compatible lockfile.
- **AWS OIDC authentication (`aws-actions/configure-aws-credentials@v5`)** — because it eliminates the risk of leaked long-lived static AWS access keys by using short-lived STS tokens.
- **Unprivileged `nodejs` system user (UID 1001, GID 1001)** — because running containers as non-root mitigates container breakout security vulnerabilities.

## Dead Ends

- **Tried:** Building container without explicit `NITRO_PRESET=node-server` → **Failed because:** Nitro output a Cloudflare Worker handler (`export default { fetch }`), causing the Node.js runner to exit immediately without binding an HTTP socket. Resolved by injecting `ENV NITRO_PRESET=node-server` into the builder stage of `Dockerfile`.
- **Tried:** `npx tsc --noEmit` on raw host environment without prior `npm install` → **Failed because:** The system prompted interactively to download `tsc@2.0.4`. Resolved by running build/typecheck validation inside the Docker build pipeline and using the local repository toolchain.
- **Tried:** Running the repository-analysis helper with its default `uv` cache → **Failed because:** the default user cache location is read-only in this environment. Resolved by using a temporary cache under `/tmp/stp72-company-uv-cache`.
- **Tried:** Trusting the automatic `workflow-orchestrator` classification → **Rejected because:** it was based on generic path/package signals. Direct source inspection establishes a content-first localized SSR website.

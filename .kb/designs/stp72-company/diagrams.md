# STP72-company — Diagrams

## Component Map

```mermaid
graph TD
  Browser --> Nitro[Nitro fetch server]
  Nitro --> Start[TanStack Start middleware]
  Start --> Router[TanStack Router]
  Router --> Root[Root document and QueryClient]
  Router --> LocaleRoutes[Locale-aware route files]
  LocaleRoutes --> Registry[Route and solution registries]
  LocaleRoutes --> Content[Typed content dictionaries]
  LocaleRoutes --> Templates[Page templates]
  Templates --> Shell[PageShell]
  Shell --> Header[Header, search, locale controls]
  Shell --> Main[Page content]
  Shell --> Footer[Footer]
```

`src/routeTree.gen.ts` is generated from the four route files. It should be regenerated by the bundler, never hand-edited. File-based routing and generated trees are the intended TanStack Router model; see the [official routing documentation](https://tanstack.com/router/latest/docs/routing/file-based-routing).

## Execution Flow

```mermaid
flowchart TD
  StartRequest[Request arrives] --> Middleware[Error and CSRF request middleware]
  Middleware --> ServerEntry[Load TanStack Start server entry]
  ServerEntry --> RouteMatch[Match generated route tree]
  RouteMatch --> Validate{Valid localized route?}
  Validate -->|No| FourOhFour[404 component]
  Validate -->|Yes| Resolve[Resolve stable content key]
  Resolve --> Head[Build SEO head]
  Resolve --> Render[Render PageShell and template]
  Head --> Render
  Render --> Response[SSR response]
  Response --> Normalize{Swallowed h3 JSON 500?}
  Normalize -->|Yes| ErrorHTML[Safe HTML 500]
  Normalize -->|No| Send[Send response]
```

The two failure paths are intentionally different: a known missing localized slug is a 404; an unexpected runtime failure becomes a generic HTML 500 without leaking details.

## State Diagram: Theme Preference

```mermaid
stateDiagram-v2
  [*] --> System: no saved preference
  System --> Light: system light
  System --> Dark: system dark
  Light --> Dark: toggle
  Dark --> Light: toggle
  Light --> System: storage removed externally
  Dark --> System: storage removed externally
```

The initial inline document script applies the saved/system result before first paint. The provider then maintains the state and listens for operating-system changes only when preference is `system`.
